FIXES APPLIED (2026-11-12, code pass on Rog CPU by ScareCrow:Nvidia;

B1 (comma-split) - FIXED in resolve_targets(). Old code `return
list(target_arg)` char-split the comma string ("q_proj,k_proj" -> 17
single-character module names -> lane 3's NoMatchingPeftModuleError in run
2). Now:
    return [t.strip() for t in target_arg.split(",") if t.strip()]
Single-name inputs preserved ("q_proj" -> ["q_proj"]); whitespace and
trailing commas tolerated. The HOUSE default --target-modules (comma
string of the 7 projections) now resolves to the 7-name list as intended.

B2 (QAT-wrapper catch) - FIXED in resolve_all_linear()/resolve_targets().
New _is_quant_wrapper() excludes quantization wrapper Linears by class
identity over the whole MRO (fragments "quant" / "clippable" -> catches
QuantizedLinear, which SUBCLASSES nn.Linear, and Gemma4ClippableLinear).
Excluded wrappers are counted and printed
("[lora] all-linear: excluded N quantization wrapper module(s) ..."); if
NOTHING wrappable remains (QAT-direct base), resolve_targets raises
SystemExit with a clear "unsupported ... needs a dequantized/16-bit base"
message instead of feeding peft the cryptic "Target module
Gemma4ClippableLinear(...) is not supported" from run 3.

HONESTY NOTES (things the fix does NOT do):
- The wrapper exclusion is a class-MRO identity check, not a hard isinstance
  import: the wrapper classes exist only in transformers 5.15.1 (GPU lane;
  Rog has 4.51.3), so importing them would crash elsewhere. The MRO check is
  isinstance-equivalent against those bases for matching purposes.
- Post-fix, `--target-modules all-linear` on a QAT-direct checkpoint
  resolves to the NON-wrapper real linears only (or refuses cleanly if
  none) - it no longer requests the QAT-wrapped projections at all. The
  declared T4 lane (unsloth + HOUSE 7-name default targets) is unaffected:
  7 explicit names, no all-linear resolution, patched peft wraps the QAT
  modules as it did in run 4.
- The transformers QuantizationMethod.GEMMA training refusal (run 5) is
  upstream (transformers), untouched by both fixes.
